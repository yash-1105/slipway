# 0004 — Novita base URL and API surface

**Status:** Proposed — blocked on a live verification call
**Date:** 2026-08-24

## Context

Novita's documentation shows three different base paths for its
OpenAI-compatible surface:

- `https://api.novita.ai/openai/v1`
- `https://api.novita.ai/openai`
- `https://api.novita.ai/v3/openai`

The OpenAI SDK appends `/chat/completions` and `/models` to whatever
`base_url` it is given, so exactly one of these is correct for us and the other
two produce 404s that look like authentication or model-name problems. This
must be settled by observation, not by picking the one that appears most often
in the docs.

Separately: Novita does **not** implement the Responses API. Chat completions
only. Code that reaches for `client.responses.create` will fail at runtime, not
at import.

## Decision (pending)

`https://api.novita.ai/openai/v1` is the working assumption recorded in
`app/config.py` as the default for `SLIPWAY_NOVITA_BASE_URL`. It is
**unverified**.

Before this ADR moves to Accepted, run:

    make models-sync          # scripts/sync_models.py

which performs a real `GET {base_url}/models` against each of the three
candidate paths with a live key, records which returned 200, writes the model
list to `config/models.yaml`, and prints the result to paste into this ADR.

`config/models.yaml` is generated by that script and is never hand-edited. No
model id is ever typed from memory anywhere in the codebase; every call site
resolves a logical role ("spec", "build", "review") through the file.

## Consequences

- Until the verification call is made, `config/models.yaml` contains no model
  ids and the models seam refuses to construct a client, so the failure is at
  startup with a clear message rather than at the first agent call.
- Re-running the sync is how we discover a retired model id, so it is a
  routine operation and appears in `RUNBOOK.md` under *Provider outage*.
